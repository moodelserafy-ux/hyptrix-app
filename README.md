# Hyptrix — Cinema & Television Tycoon

مشروع لعبة ويب Mobile-First PWA مبني على Next.js App Router وReact وTypeScript، بواجهة عربية RTL ونمط سينمائي داكن. هذه نسخة MVP قابلة للتشغيل محليًا وتضم حلقة اللعب الأساسية، مع نقاط تكامل واضحة للخدمات الخارجية التي تحتاج مفاتيح حساباتك.

## تشغيل محلي

```bash
npm install
cp .env.example .env.local
npm run dev
```

افتح `http://localhost:3000`.

> لا يمكن تشغيل البناء أو التحقق النهائي من الاعتمادات داخل بيئة الإنشاء الحالية لأن تثبيت حزم npm لم يكتمل هنا. بعد `npm install` شغّل `npm run lint` ثم `npm run build` في بيئتك.

## ما تم تنفيذه

- تأسيس الاستوديو: الاسم، المدير التنفيذي، السوق المصري، ميزة المؤسس، ومصمم شعار مركب. 10 رموز × 5 إطارات × 5 باليت = 250 تركيبة SVG أصلية.
- تطوير المشاريع: فيلم أو مسلسل، 7/10/15/30 حلقة، رمضان أو خارج الموسم، تصنيف أساسي وفرعي، تقييم عمري، وملخص قصة/سيناريو حر. تظهر ميزانية الإنتاج والتسويق والشاشات بعد موافقة الطاقم.
- تشكيل الطاقم: مخرج، ورشة كتابة من مؤلف أو اثنين، مدير تصوير، موسيقار، مونتير/VFX، وبطاقات ممثلين بمستويات وإحصائيات. الحد الأدنى خمسة ممثلين.
- تفاوض وأجور: خصم مؤسس المفاوض، مؤشر Ego، وزر عزومة VIP عبر Rewarded Ads.
- التصوير والأزمات: أزمات مرتبطة بالمشروع تُولّد عبر AI مع بديل محلي متعدد الخيارات، وتؤثر على السيولة والضجة والجودة، وتمويل طارئ كمكافأة إعلانية.
- التوزيع والطرح: محاكاة منافسين، تقييم نقاد وجمهور، مضاعف الإيرادات، مانشيتات ومنشورات ومراجعات.
- الذاكرة التراكمية والجوائز: يسجل `world_history` الإصدارات والأزمات والجوائز، ويُرسل كسياق لتقييمات AI اللاحقة.
- مشاركة فيروسية: تحويل بطاقة البوستر والنتائج إلى PNG عبر `html-to-image`.
- تخزين محلي: Zustand persist مع `idb-keyval` / IndexedDB. لا تُرسل ملفات المشاريع أو السيناريوهات إلى Supabase.
- PWA: manifest وservice worker أساسي لقشرة التطبيق.
- نظام استيراد JSON في شاشة التأسيس والإعدادات مع تحقق Zod ودمج بالـ`id` والحفاظ على القيم الافتراضية عند غياب الحقول.

## قاعدة البيانات الخارجية

الهيكل المرجعي موجود في `data/default_db.json`. جميع الكيانات المدمجة خيالية، ولا تحتوي ملفات المصدر الافتراضية على أسماء ممثلين أو شركات أو منصات أو مهرجانات حقيقية.

يمكن استيراد ملف JSON من الجهاز أو جلب رابط مباشر HTTPS/HTTP. روابط GitHub يجب أن تكون Raw، ويجب أن تسمح الاستضافة بـCORS عند الجلب من المتصفح. حد الحجم 5MB. يتم تخزين الحزمة في IndexedDB مع بيانات اللاعب.

تعمل `getResolvedDatabase()` على دمج السجلات بحسب `id`: الحقول الموجودة في الحزمة الخارجية تستبدل الحقول المناظرة، والحقول الغائبة تظل من قاعدة البيانات الافتراضية؛ ويشمل ذلك الإحصائيات والقدرات المتداخلة.

## Groq ثم Gemini

أضف هذه المفاتيح في `.env.local`:

```dotenv
GROQ_API_KEY=...
GROQ_MODEL=openai/gpt-oss-120b
GEMINI_API_KEY=...
GEMINI_MODEL=gemini-3.8-flash
```

يستدعي `/api/generate-event` Groq أولًا، ثم يحاول Gemini عند فشل الاتصال أو تجاوز الحصة. الإعداد الافتراضي الحالي هو `openai/gpt-oss-120b` في Groq و`gemini-3.8-flash` في Gemini، ويمكن تغييرهما عبر متغيرات البيئة. تم تجنب معرفات Llama 3 القديمة افتراضيًا لأن Groq أعلن إيقافها لمستويات المطورين في 16 أغسطس 2026. يتم فحص JSON الناتج بمخطط Zod. عند عدم توفر المزودين، يعمل تقييم محلي deterministic كـfallback حتى لا تتوقف اللعبة. لا تُرسل مفاتيح المزود للمتصفح.

## Supabase

1. أنشئ مشروع Supabase.
2. شغّل `supabase/schema.sql` داخل SQL Editor.
3. أضف القيم التالية إلى `.env.local`:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
SUPABASE_SERVICE_ROLE_KEY=...
```

Supabase محصور في Auth، محفظة VIP وحالة الباقة، ولوحة المتصدرين. جداول الرصيد والاشتراكات وأحداث الإعلانات لا تملك سياسات كتابة للعميل. لا تضع `SUPABASE_SERVICE_ROLE_KEY` في متغير يبدأ بـ`NEXT_PUBLIC_`.

## Rewarded Ads / Offerwalls

الواجهة تستدعي Adapter موحدًا عبر:

```ts
window.HyptrixAds = {
  showRewarded: async (placement) => ({
    completed: true,
    receipt: "signed-provider-receipt"
  })
};
```

`placement` إحدى القيم: `vip_pass`, `vip_dinner`, `gulf_rescue`, `reputation_campaign`, `festival_pr`.

هذا الجسر ليس SDK إعلانيًا جاهزًا بذاته. اربط Monetag أو AdMob أو Unity Ads أو مزود Offerwall في طبقة adapter منفصلة، واجعل `receipt` إيصالًا موقعًا/قابلًا للتحقق من المزود. لا تُرجع `completed: true` إلا بعد callback حقيقي من SDK.

لتفعيل مشاهدات تجريبية محلية فقط:

```dotenv
NEXT_PUBLIC_ENABLE_AD_DEMO=true
```

المحاكاة متاحة في وضع التطوير فقط ولا تصدر إثبات مشاهدة حقيقيًا ولا تُنشئ اشتراك VIP سحابيًا.

### التحقق الخادمي من VIP

أضف:

```dotenv
AD_REWARD_VERIFY_URL=https://your-ad-verifier.example/verify
AD_REWARD_VERIFY_SECRET=...
```

يستقبل `/api/vip/rewarded` الإيصال من العميل، ثم يرسله إلى خدمة التحقق المحددة على الخادم. يجب أن تتحقق تلك الخدمة من توقيع مزود الإعلان/Server-Side Verification وأن تعيد فقط عند نجاح التحقق:

```json
{ "verified": true, "event_id": "unique-provider-impression-id" }
```

يُمرَّر `event_id` إلى دالة SQL خادمية ذرية مع قيد uniqueness لمنع إعادة استخدام الإيصال. تتقدم سلسلة VIP خمس مشاهدات موثقة وتُصفّر بعد التفعيل أو بعد فجوة 24 ساعة. كما تتحقق المكافآت السياقية من الإيصالات نفسها قبل منح تأثيرها. بعد خمس مشاهدات VIP موثقة، ينشئ الخادم اشتراكًا لمدة 24 ساعة في `vip_subscriptions`. لا تمنح مكافأة فعلية من واجهة العميل وحدها.

## استكشاف أخطاء النشر على Vercel

- عند ظهور `result is possibly undefined` في `components/game-shell.tsx`، تأكد أن `renderResults` يبدأ بالتقاط `project` و`result` ثم يفحصهما قبل استخدامهما. هذه النسخة تتضمن الإصلاح.
- إذا ظهر `studio is possibly null`، استخدم `activeStudio` الملتقط بعد بوابة التأسيس، ولا تستخدم `studio` مباشرة داخل دوال عرض الشاشات.
- تحذير `Unknown env config "cache-dir"` لا يوقف البناء. راجع **Vercel → Project → Settings → Environment Variables** واحذف متغير `NPM_CONFIG_CACHE_DIR` أو `npm_config_cache_dir` إن كان مضبوطًا يدويًا، ثم أعد النشر.
- تأكد أن **Root Directory** في Vercel يشير إلى مجلد `hyptrix` داخل المستودع، وأن أمر البناء هو `npm run build`.
- لا توجد وسيلة تضمن استحالة ظهور أخطاء مرتبطة بمتغيرات البيئة أو إعدادات حساب الاستضافة؛ اختبر نشر Preview بعد كل تحديث.

## ملاحظات وحدود النسخة

- لا يوجد مزود إعلانات فعلي مُضمّن؛ يلزم SDK/adapter وحساب ناشر وإعداد SSV.
- لا يوجد شراء VIP مباشر/بوابة دفع في هذه النسخة. رصيد VIP والباقة يُقرآن من Supabase فقط، وتغييرهما يجب أن يتم من webhook/وظيفة خادمية موثوقة.
- أزمات التصوير تُطلب من Groq ثم Gemini عبر `type: "crisis"`؛ إذا فشل الاتصال أو كان الرد غير صالح، تستخدم اللعبة أزمة محلية بديلة حتى لا يتوقف بدء التصوير.
- بيانات لوحة المتصدرين يرسلها اللاعب بعد تسجيل الدخول، لذلك هي لوحة مجتمع/ترتيب ذاتي الإبلاغ وليست اقتصادًا خادميًا مقاومًا للغش؛ الحفاظ على تقدم محلي بلا تكلفة خادم يعني عدم إمكان إثبات صافي ثروة اللعبة من جهة موثوقة.
- مؤشرات شباك التذاكر والأجور هي توازنات لعب ابتدائية قابلة للضبط، وليست توقعات مالية واقعية.
- استيراد الصور يستخدم روابط مباشرة مخزنة في الحزمة؛ عرض صورة URL خارجية يحتاج إضافة مكون عرض مناسب وسياسة CSP/remote image حسب الاستضافة.

## Hyptrix — Studio Workflow & Living World Update

تم تحديث دورة اللعب لتصبح قائمة على مراحل واضحة بدل اعتماد المشروع والطاقم والميزانية دفعة واحدة:

1. **تطوير الفكرة:** اكتب اسم العمل، الصيغة، التصنيفات، التقييم العمري، وملخص القصة والنهاية.
2. **اختيار الطاقم:** انتقل إلى كتالوج بصري كامل للممثلين والطاقم الفني. يمكن اختيار مؤلف أو ورشة من مؤلفين اثنين.
3. **عرض الفكرة والتفاوض:** يرسل الاستوديو عروضًا مستقلة لكل عضو في الطاقم. تظهر الموافقة أو الرفض مع سبب مخصص. يستخدم المسار `/api/generate-event` نوع `negotiation` مع Groq ثم Gemini، ويعمل بقرار محلي احتياطي عند تعذر مزودي AI.
4. **انتظار الردود:** يوم اللعبة يساوي دقيقة حقيقية بعد تأسيس الاستوديو، ولا توجد أزرار لتخطي الأيام. تتم مزامنة الساعة مع الوقت الفعلي، بما في ذلك تأخير علامات التبويب في الخلفية، وعند العودة تُحتسب الأيام المنقضية (بحد أقصى 90 يومًا لكل مزامنة). تحديث رد كل عضو مستقل حتى لا يستبدل رد عضو آخر عند وصول الإجابات بالتوازي.
5. **الميزانية والتصوير:** لا تظهر أدوات ضبط الميزانية إلا بعد موافقة كل أفراد الطاقم. يحدد اللاعب ميزانية البنود والتسويق والشاشات والمنصة، ثم يعرض المحرك موعد انتهاء تصوير مخططًا. تُولّد أزمات التصوير من AI مع مجموعة محلية بديلة عند تعذر المزود.
6. **الطرح وتتبع الشباك:** لا تُسجل الإيرادات المتوقعة كلها فور الإطلاق. يبدأ العمل بإيراد افتتاحي ثم يتراكم الشباك يومًا بيوم، مع تحديث إيرادات المنافسين بالتوازي ومزامنة كل يوم مرة واحدة فقط.
7. **أخبار العالم:** كل ثلاثة أيام داخل اللعبة يطلب النظام خبرًا سياقيًا من AI، ويضيفه إلى ذاكرة العالم. مراجعات النقاد تتكون من ثلاثة أصوات منفصلة: ناقد سيناريو، وصحفي جماهيري، وناقد فني، مع محرك مراجعات محلي بديل.

**ملاحظة تشغيلية:** الساعة الافتراضية تعمل من خلال جلسة المتصفح، وتُستكمل الأيام التي انقضت عند إعادة فتح اللعبة. إذا لم تُضف مفاتيح Groq/Gemini، تستخدم اللعبة قرارات محلية احتياطية؛ لذلك يجب ضبط مفاتيح AI في Vercel للحصول على أسباب تفاوض وأخبار ومراجعات مولدة فعليًا.
